# Move Node to 22.23.4

Date: 2026-10-23. PR: #26. Tier: T3.

## Intent

`.nvmrc` pins Node 22.21.0, and CI, the deploys and the watch all read it. Two Dependabot pull
requests now fail at `.adlc/install`, before any test runs:

- #18, the grouped npm update: astro 7.4.1 needs Node `>=22.22.0`
  ([job 120704776534](https://github.com/anandfrancis93/portfolio/actions/runs/40038824781/job/120704776534)).
- #20, html-validate 11.17.0: it needs Node `^22.22.0 || >= 24.8.0`
  ([job 120703941222](https://github.com/anandfrancis93/portfolio/actions/runs/40038565364/job/120703941222)).

`.npmrc` sets `engine-strict=true`, so pnpm refuses the install. Plan 001 recorded the same block
on 2 September 2026: html-validate stayed on 10.x because every 11.x release needs Node 22.22.

Node 22.23.4 (20 October 2026) is the newest 22.x release and a security release
([Node.js release index](https://nodejs.org/dist/index.json)). 22.21.0 is five security
releases behind it: 22.22.0, 22.22.2, 22.23.0, 22.23.2 and 22.23.4.

Constraints:

- Node stays on the 22 line. A move to 24 is its own change.
- The owner's MacBook needs Node 22.23.4 too. `nvm install` reads `.nvmrc`.

Done when: `adlc / checks` passes here, and then #18 and #20 get past `.adlc/install` after
they rebase.

## Tests to add

None. The failing checks already exist: the install step of #18 and #20, linked above.
`adlc / checks` on this pull request runs the whole suite on 22.23.4.

## Files in scope

- `.nvmrc`: 22.23.4.
- `package.json`: `engines.node` to `>=22.22`, the lowest version the pending updates accept.
- `README.md`: the same minimum.
- This spec.

## Out of scope

- Node 24.
- The pnpm version.
- The dependency updates in #18 and #20 themselves.

## Decision

- Choice: pin 22.23.4, the newest 22.x release, and declare `>=22.22` as the minimum.
- Alternatives: pin 22.22.0, the lowest version both updates accept; move to Node 24.
- Why: 22.23.4 carries the latest security fixes, and Node keeps backward compatibility within
  a major line. 22.22.0 would leave known security fixes out. Node 24 changes the major version
  for every workflow at once, which is more than these updates need.
